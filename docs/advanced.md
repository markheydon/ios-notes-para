# Optional extras

Set the basic system up first and use it for a couple of weeks. Add something from this page only when a specific friction shows up, and add one thing at a time. Every extra tag or Smart Folder is a decision you must make during organise, so each one has to earn that cost.

## Overlay tags

`#work` and `#personal` are the only overlay tags this guide recommends. Use them when one PARA tree serves both a job and a home life, and you sometimes want to hide one of those worlds.

A Smart Folder can show `#work` across **Projects**, **Areas**, and **Resources**. That is a view. The notes still live in PARA folders.

Do not add `#q3`, `#waiting`, or a tag per client. Waiting and contexts belong in Reminders. Clients are either projects, areas, or a word in the title.

## Smart Folders as views, never as homes

Create a Smart Folder from the folder list: New Folder, then **Make into Smart Folder** (wording varies). Give it filters. Do **not** do this to **Projects**, **Areas**, **Resources**, **Archives**, or the built-in **Notes** folder.

Useful views:

| Smart Folder | Filter idea | Use it when |
| --- | --- | --- |
| Untagged | Notes with no tags, if you use overlay tags | A second look at Inbox after filing |
| Recently edited | Last edited in the past week | Friday review, if the folder list feels abstract |
| Locked | Locked notes | Check what you have hidden from search on other devices |

If you never open the view, delete it. Smart Folders are cheap to recreate and expensive to feel guilty about.

## Note links and a light index

If **Projects** is still hard to scan, one index note at the top of **Projects**, pinned, with links to each active project, can help. Update it in the weekly review. If you skip the update, delete the index; a stale map is worse than the folder list.

The same pattern works inside a large area subfolder. It does not work as a site-wide wiki. Notes will not show backlinks.

## Apple Intelligence

On a supported device, Intelligence can summarise, proofread, or rewrite a note. Use summarise as a draft of the two-line summary in [find it and use it](retrieve-and-express.md). Do not let it file notes into PARA for you. Filing is a commitment question, and the model cannot know whether you are actually going to finish the loft.

## Pairing with Reminders GTD

The two guides are meant to sit together:

| In Notes | In Reminders |
| --- | --- |
| Project note (material, outcome, drafts) | Project reminder (outcome) with tagged subtasks |
| Area note (standard, reference) | Area sections on the Projects list |
| Resource note | Usually nothing, unless a someday action appears |
| Archives | Completed or dropped reminders |

Paste the Notes title into the reminder notes field, or add a note link if your version makes that easy. One direction is enough.

Do not tick checklists in Notes *instead of* completing Reminders actions. You will believe the project is moving when only the prose is.

See [Reminders GTD](https://markheydon.me.uk/ios-reminders-gtd/).

## Files app mirror

If you keep large PDFs or video outside Notes, you can mirror the four folder names in iCloud Drive. That is optional. If you do it, keep the names identical (**Projects**, **Areas**, **Resources**, **Archives**) so you are not maintaining two taxonomies. Notes remains the index: a line in the project note that says “full dump in Drive / Projects / Kitchen”.

## Shortcuts

The Shortcuts app can create a note in a folder. If you automate capture, send it to the built-in **Notes** folder, not to **Projects**. A shortcut that asks “which PARA folder?” is organise at capture time, which this guide is trying to prevent.

## A Goals folder

Some people add a fifth top-level folder for annual goals. This guide does not. Goals that are actual projects belong in **Projects**. Longer pictures belong in one area note, or in the horizons note you already use for GTD. A fifth bucket becomes a second inbox for wishes.
