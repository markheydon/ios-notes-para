# Why this is worth doing

PARA is a way to sort everything you might need later into four places, by how soon you will act on it. Tiago Forte’s names for those places are Projects, Areas, Resources, and Archives. The point is not a prettier folder tree. The point is that when you sit down to finish something, the material is already sitting with that work.

This guide is written for Notes on iOS 27 and iPadOS 27. Notes can be that system on an iPhone or iPad, because capture is already with you. The share sheet, Quick Note, Siri, widgets, and the compose button can land a thought before you have decided which folder it belongs in. On iPhone, Control Centre and the Action button are extra capture paths. The rest of this guide is how to decide, and how to find the right note when you are actually doing the work.

## What usually breaks

People abandon a second brain for a boring reason. Capture stays easy. Filing becomes a second job. The default **Notes** folder fills with untitled screenshots, and search becomes a lottery. The fix is a smaller system you will still open on a tired Thursday, plus a review short enough to finish.

A second failure mode is taxonomy. A folder for every client, year, and hobby feels thorough on day one and becomes archaeology by day ten. This guide keeps the required folders to four, plus the inbox you already have.

A third failure mode is mixing tools. Notes is a poor task manager. Reminders is a poor filing cabinet. If a line is something you must *do*, it belongs in Reminders. If it is something you must *find*, it belongs here. The sibling [Reminders GTD](https://markheydon.me.uk/ios-reminders-gtd/) guide is the action half of the same idea.

## Actionability, not topic

Classic notebooks assumed you would remember which subject a fact lived under. PARA assumes you will remember the project or area you are in. “Graphic design” is a resource topic. “Launch the shop page” is a project. The same screenshot can belong in either, depending on whether you will use it this month.

The question that settles most cases:

- Is there a **finish line**? It is a project.
- Is it an **ongoing standard** you keep? It is an area.
- Might you **need it later**, with no current commitment? It is a resource.
- Is it **done, paused, or no longer yours**? Archive it.

## Starting again after a messy library

You do not need a new app, and you do not need to design the perfect areas before you begin.

Give yourself one sitting:

1. Follow [setup](setup.md) if the four folders are not there yet. Leave old notes where they are until step 3.
2. For twenty to forty minutes, dump anything still in your head into a new note in the **Notes** folder. Speak it to Siri if typing feels heavy. Projects, quotes, links, “I should write this up”, all of it. Capture is allowed to be messy.
3. File the **Notes** folder using the questions in [capture and organise](capture-and-organise.md) until it is empty enough to trust. Old folders can wait. Move anything still true into **Notes** and run it through the same questions. Delete the rest. Deleting a stale note is a successful outcome.
4. Do the [weekly review](weekly-review.md) once, lightly.
5. Stop. Open one project note and do something with it.

Archives is allowed to be untidy. Inbox is not. The review is what makes the difference.

## A system you will keep

Trust comes from two promises you can keep:

- Every note has a home, and the **Notes** folder gets cleared.
- When you open **Projects**, you see the work you are actually in, not last year’s hobbies.

The weekly review is the practice. The folders are just how the phone groups the material.
