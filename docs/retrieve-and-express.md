# Find it and use it

A second brain that you only fill is a landfill. PARA earns its keep when you open a project note and make something: an email, a decision, a draft, a call.

The second half of CODE is Distill and Express. Distill is making the note easier to reopen. Express is actually using it.

## Find the note

Try, in this order:

1. **Projects**, if you know the work you are in. Open the outcome note. That is the point of filing by actionability.
2. **Search**, from the folder list or inside a folder. Use a word you would have put in the title.
3. **Areas**, if the thing is a standard (insurance, health, a job role) rather than a project.
4. **Resources**, if you are researching and are not committed yet.
5. **Archives**, if you know it ended. Search still covers Archives; you rarely need to browse it.

If search fails, the title was too vague. Rename it now. That is part of distill.

Pinned notes at the top of a folder are for the handful you reopen this week, not for everything important in your life.

## Distill in Notes (no highlighter plugin)

Progressive summarization in other apps uses layers of highlight. Notes does not have that plugin. Use the formatting you already have.

A practical stack, applied only when you reopen a note to *use* it, not when you capture:

1. **Title** already says what it is.
2. Put a **two-line summary** under the title the first time you actually need the note. Future you should be able to stop there.
3. Use **Headings** for the sections you return to. On current iOS, a heading can collapse. Collapse the raw dump; leave the summary visible.
4. **Bold** the few sentences you would quote. Do not bold whole paragraphs.
5. Delete or archive attachments you will never open again.

Do not distill on capture day. Distill the second time the note earns your attention. Notes you never reopen can stay messy in **Resources** or **Archives**.

Apple Intelligence can summarise a long note on a supported device. Treat that summary as a draft of step 2. Read it. If it is wrong, write the two lines yourself. A confident wrong summary is worse than an unread wall of text.

## Express

Open the project note *before* you start the output. That sounds ceremonial. It is not. The alternative is hunting Safari history while the meeting has already begun.

From the note:

- Copy the facts you need into the email, message, or document you are actually producing.
- Add a heading “Used in…” with the date and what you made, if that helps you trust the pile.
- If the work produced a new artefact worth keeping, paste a link or drop the file back into the same note.

Express is the reason Inbox gets emptied. You cannot ship from a thousand unfiled screenshots.

## Link related notes

When two notes should stay related, put a link in each (or at least in the one you will open first). In a note, tap the insert / link control and choose another note. The exact button moves around; you are looking for a link to an existing note, not a web URL.

Keep this rare. Three links from a project note to supporting resources is useful. A web of everything is Obsidian, and you did not pick Obsidian.

## When you cannot find it

If a note is missing, it is usually still in **Notes** (never filed), under the wrong PARA folder (filed by topic), or titled “Meeting”. Search for a unique word from the body. Then file it correctly and rename it.

If this happens every week, your filing questions are too clever. Go back to the finish-line test in [the model](model.md).
