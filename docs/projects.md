# Projects, areas, and archives

PARA looks like four folders. Most of the judgement sits in the first two.

## Projects

A project is a result with a finish line that you have agreed to. “Website refreshed” is a project. “Marketing” is not.

Default shape:

- One note, titled as the outcome.
- First lines: what done looks like, and any deadline that exists in the real world.
- Then the material: links, scans, meeting notes, drafts.
- A short checklist of *open questions* or *pieces of material still missing*, if that helps. This is not your next-action list.

When the project grows several genuine pages - a long hire, a house move - make a **subfolder** under **Projects** with the same outcome name, and put the notes inside. The folder is the project. Do not also keep a stray copy in the **Projects** root.

How many active projects? If **Projects** takes more than a minute to scan, some of those notes are areas, resources, or wishes. Move the wishes to **Resources** or [Reminders Someday](https://markheydon.me.uk/ios-reminders-gtd/), and archive anything you are not actually doing this season.

When the outcome is done:

1. Tick any remaining checklist rows that were about the work.
2. Move the note (or subfolder) to **Archives**.
3. Complete or drop the matching reminders in Reminders.

Do not delete finished project notes by default. You will steal from them later. Archives is cheap.

## Areas

An area is a standard you maintain. Health, money, a job role, a relationship, the house, a team you lead.

Default shape:

- One note per area, or a subfolder if that area collects many notes (for example **Areas → Money** with insurance, tax references, and a household inventory).
- The top of the note states the standard in one line: “Stay on top of the boiler and the certificates”, not a manifesto.
- Recurring reference belongs here: policy numbers, routines, the document you always need. Recurring *actions* belong in Reminders.

Projects grow out of areas. “Boiler serviced” is a project that, when finished, may leave a new certificate in the **Areas → Home** note. File the project while it is alive. File the lasting record in the area when it is over. You can link the two.

If an area goes dormant - you sold the car, you left the club - move it to **Archives**. Dormant is not deleted.

## Resources

Resources are topics without a current commitment: a craft you might take up, article clippings, how a library works, a vendor you might use.

Keep the folder flatter than you think. Prefer one note titled “Invoice templates” over nested folders for every format. Search will save you. Nested resources become a garden you never walk.

When a resource suddenly has a finish line, you have a project. Either:

- Move the note into **Projects** and rename it to the outcome, or
- Leave the resource where it is and start a new project note that links to it.

The second option is better when the resource will outlive this particular project.

## Archives

Archives is not a bin. It is the active folders’ off switch.

Move here:

- Finished projects
- Paused projects you are willing to forget until search or a review surfaces them
- Areas you no longer hold
- Resources you have gone cold on

You can nest by year if the folder becomes huge (**Archives → 2025**), but you do not have to. Search includes Archives.

Do not browse Archives for fun in the weekly review. Glance only if you are looking for something specific to revive. Revival is a move back to **Projects**, **Areas**, or **Resources**, plus a next action in Reminders if the revival is real work.

## Work versus personal

If work and home share one iCloud account, keep a single set of PARA folders. Split with `#work` and `#personal` if you must filter, or with a prefix in the title: “Work: Q3 launch”, “Home: loft clear-out”. Two complete PARA trees (Work/Projects and Home/Projects) doubles the filing questions. One tree is enough for almost everyone.

Shared iCloud folders and collaborative notes are fine for a single shared outcome. Prefer sharing that one note or subfolder, not the entire **Projects** tree.
