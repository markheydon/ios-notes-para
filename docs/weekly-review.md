# The weekly review

This is the habit that makes the rest true. Without it, the built-in **Notes** folder fills with screenshots, **Projects** still lists last quarter’s work, and you stop trusting search.

Keep it short enough that you will do it when you are busy. Thirty quiet minutes is plenty once the system is in motion. The first review after a long break takes longer because you are filing a backlog, and that longer sitting is the restart described in [why](why.md).

Do it on a phone, once a week, at a time you already protect. Friday afternoon or Sunday evening both work. A repeating reminder in Reminders, titled “Notes weekly review”, is enough of a nudge. Put the checklist below in a note in **Areas** (or in Reminders, if that is where your other review lives) so you are not reinventing it.

## Get clear

**Empty the Notes folder.** File every item with the questions in [capture and organise](capture-and-organise.md). Inbox at zero, or zero except today’s leftover captures, is the definition of done for this step.

**Trash the obvious.** Duplicate scans, expired codes, empty notes. Recently Deleted will hold them.

## Get current

**Open Projects.** For each project note or subfolder:

- Is the outcome title still what you are committed to?
- Are you still doing this *this season*? If not, move it to **Archives** (paused) or **Resources** (it was never a commitment).
- Does Reminders still have a next action, if this project requires doing rather than only writing? If the note is waiting on work you will not remember, that is a Reminders problem, not a Notes problem.
- Has finished material been left in the project when it now belongs in an area note?

A project with no activity and no finish in sight is usually an area or a wish. Move it.

**Scan Areas.** You are not rewriting your life. Check that each area note still matches a standard you hold. Archive the ones that do not. If an area has sprouted a finish line (“renew the insurance by Friday”), promote that slice to a project note and leave the rest in the area.

**Do not browse Resources or Archives.** Search will find them. If Resources has become a second inbox, steal ten minutes to delete or file the worst of it, then stop.

## Get creative

**Open one area or resource you care about** and ask whether anything there wants to be a project. If yes, create the project note, file supporting material, and put a next action in Reminders. If nothing has, you are finished.

This is Forte’s “express” habit at weekly scale: use the library, do not only tidy it.

## After the review

Tick the checklist. Then stop reviewing and open one project note in the context you are actually in. Write, send, or decide. The review serves the work. It is not a second job.

If you also run [Reminders GTD](https://markheydon.me.uk/ios-reminders-gtd/), do that review in the same sitting. Empty Notes, then empty Reminders Inbox. Projects in both apps should tell the same story: if Notes still has “Kitchen tap fixed” and Reminders does not, add the next action or archive the note.

## When you miss a week

Do the next one. Start at the **Notes** folder, then **Projects**. Skip Areas if time is short. A slightly stale system you review is still a system. A perfect taxonomy you avoid is not.
